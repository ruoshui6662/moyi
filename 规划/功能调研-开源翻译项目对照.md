# 功能调研 — 开源翻译项目对照（2026-09-23）

> **性质：纯调研，未改任何代码。**
> 方法：逐项目抓 GitHub README / API 实测（数据截至 2026-09-22），与墨译当前能力做差集。
> 不确定处显式标注；不编造。

## 〇、墨译能力基线（对照用）

Chrome MV3 + 油猴双端（共享核心）：整页双语对照（流式逐段、视口优先 + 1400px 窗口预取、段落缓存 7 天、长文滚动补扫）；OpenAI 兼容多模型 / 自定义 / Ollama 本机 + DeepL / 腾讯 / 微软 / 谷歌；六种译文样式 + 排版调节；贴边悬浮球；应用内 + 系统快捷键；YouTube / X 双语字幕（规则断句 + AI 断句）；closed Shadow DOM 设置（明暗双套）。
已规划未做：Edge TTS 朗读、侧边栏、词典查询、配置历史、Firefox 适配。

## 一、重要事实勘误（影响"能否借鉴实现"）

- **沉浸式翻译主仓库已不开源**：仓库仅发布 Release + 收集反馈，旧开源版 2023-01 归档（[仓库](https://github.com/immersive-translate/immersive-translate)）。功能情报只能来自官网/文档，**不能读码借鉴实现**。
- **Trancy 为闭源商业插件**（官网/商店无源码链接，[Chrome 商店](https://chromewebstore.google.com/detail/mjdbhokoopacimoekfgkcoogikbfgngb) 显示 30 万用户）——只能抄产品方向，看不到实现。
- Read Frog 为 GPL-3.0 + 商业双许可；FluentRead 8,187★ GPL-3.0；Saladict 13.3k★ MIT；KISS Translator 12.6k★ MIT，**与墨译同构**（扩展 + 油猴双端、轻量路线）——这三家是可放心读码借鉴的。
- OmnicTranslator / SmartLingo / Toucan 本次**无法核实**（GitHub 无结果 / 网站不可达），不采信。

## 二、逐项目功能要点（含来源）

### Immersive Translate（18,988★，[官网](https://immersivetranslate.com/) / [文档](https://immersivetranslate.com/docs/)）
双语网页（鼠标悬停段落翻译为创新点）、**输入框翻译**（主打卖点：任意输入框实时双语对话）、PDF 实时双语 / **ePUB 一键导出** / TXT / 字幕文件 / BabelDOC 保排版 PDF / Google Docs / Zotero、YouTube 双语字幕 + **无字幕视频翻译** + **直播/会议翻译** + 图片/漫画/区域翻译(Beta)、10+ 服务商、AI Prompt 高级配置、移动端 App、js-SDK。

### Read Frog 陪读蛙（9,808★，[README](https://github.com/mengxi-ream/read-frog)）
划词工具条（Translate / **Explain 按语言水平解释** / Speak）、**自定义 AI Actions**（可复用 prompt 工具，结果入 Notebase）、**生词本 + 闪卡 + SRS 间隔重复 + 复习统计 + MCP 接入**、上下文感知翻译、Glossary 术语表、站点规则与 Site Control、输入翻译、**配置同步与备份**、YouTube 字幕（含 AI 断句，墨译已同源借鉴）、**Edge TTS：150+ 音色、按语言映射、句子感知分块 + 预取下一块、LLM 语种检测**、**批量请求聚合宣称省 70% token + 指数退避 + 失败降级单条**。

### FluentRead（8,187★，[README](https://github.com/FluentRead/FluentRead) / [guide](https://fluent.thinkstu.com/en/guide/)）
双语/悬停/划词 + 一键还原、**AI 阅读卡片**（词义/句子分析/用法 + 带上下文**追问**）、学习中心（词汇句收藏复习）、**图片翻译 + 屏幕区域翻译**、**PDF/ePUB/DOCX 双语对照、译文可编辑、导出**、YouTube/X 字幕（部分视频**本地 AI 转录**）、Glossarys 术语表、**Chrome 内置 AI 翻译兜底**、油猴版（[greasyfork/482986](https://greasyfork.org/en/scripts/482986)）。

### Trancy（闭源，30 万用户，[官网](https://www.trancy.org/) / [manual](https://manual.trancy.org/)）
字幕平台矩阵（YouTube / Netflix / Disney+ / HBO Max / TED / edX / Coursera）、**影院模式/阅读模式**（视频缩角、字幕变文本流）、**字幕导出**、NLP 断句合并、AI 查词/语法解析/词性标注、**生词被动高亮** + Learning Deck、AITalk 口语教练（细节未核实）、PDF AI 翻译。

### Saladict 沙拉查词（13,345★，[README](https://github.com/crimx/ext-saladict)）
多查词模式组合（单击/双击/划词/悬浮/快捷键）、**场景模式**（论文/翻译/句库按场景组合词典 ≈ Profile）、聚合多词典、**生词本 + 单词上下文自动抓取 + WebDAV 同步 + Anki 自动制卡 + 导出**、发音体系（真人发音 + 长句 TTS + AB 循环变速）、**内置 PDF 阅读器划词**、OCR 图片查词、侧边栏。

### Pot（19,420★，桌面端概念，[README](https://github.com/pot-app/pot-desktop)）
划词 / **输入翻译** / **剪切板监听** / **截图 OCR + 截图翻译**、多接口并行翻译、OCR 引擎矩阵（系统级离线 Windows.Media.OCR / Apple Vision / Tesseract）、**生词本导出 Anki/欧路/有道**、**插件系统**（翻译/OCR/TTS/收藏四类扩展点）、**外部调用 HTTP API**。

### KISS Translator（12,598★，[README](https://github.com/fishjar/kiss-translator)，与墨译同构：扩展+油猴、轻量）⭐ 最有参照价值
悬停翻译、划词框（**多服务对比翻译** + 英文词典 + 收藏）、输入框翻译（Alt+I）、YouTube 字幕（基础合并 + AI 断句）、**富文本翻译**（保留链接与样式）、**规则生态：社区规则订阅/分享 + 可视化选元素编规则（范围高亮预览/撤销重做）+ 私有规则同步服务**、自定义术语 + **AI 术语词典**、聚合批量发送、**AI 上下文会话记忆**、**WebDAV/KISS-Worker 跨端同步**、Chrome 内置 AI 兜底、本地词典兜底、CustomEvent 外部触发 API、覆盖 Firefox/Safari/Thunderbird(邮件)。

彩云小译（闭源，[官网](https://fanyi.caiyunapp.com/)，SPA 只核实到功能名）：网页/文档翻译、双语对照、**术语库**。

## 四、价值/成本比 前 10 推荐（墨译视角）

1. **划词/悬停查词弹窗**——6/6 项目共现，"没有它就不完整"；与悬浮球/样式体系天然衔接；词→可顺势长出生词本。
2. **术语表（Glossary）**——半天级；AI 翻专有名词/人名的唯一轻量解；5 个项目都有。
3. **输入框翻译**——IT 主打卖点、KISS/Frog/Pot 全做；社媒 + AI 聊天双高频场景；零依赖可达。
4. **生词本（先收藏+导出，SRS 缓做）**——接住"词典查询"规划；学 Saladict 的"自动带上下文存储"。
5. **站点规则可视化编辑 + 社区订阅仓库**——学 KISS 三件套（个人>订阅>全局 + 范围预览 + 社区 repo），把"翻译覆盖率"变成社区生态护城河。
6. **批量聚合 + AI 上下文会话记忆**——Frog 实测方向（宣称省 70%），纯请求层改造，长文质量与成本双赢。
7. **配置备份/恢复 + WebDAV 同步 + 场景 Profile**——合并规划中"配置历史"，一并解决油猴多浏览器痛点。
8. **TTS 朗读**——维持规划；直接照 Frog 的工程细节做（分块预取/按语言音色/LLM 语种检测），先用系统 `speechSynthesis` 零依赖兜底。
9. **字幕导出 SRT/TXT + 平台扩展（TED/Bilibili）**——墨译字幕已领先多数，导出是小时级；平台适配按需求逐个加。
10. **AI 阅读卡（Explain + 追问）**——Frog/FluentRead/Trancy 三家同向的行业趋势；复用现有 AI 通道边际成本低。

**明确缓做（与"零依赖 + 双端"冲突最大）**：PDF/EPUB/DOCX 文档线（若做建议独立懒加载模块或服务端路线如 IT 的 BabelDOC）、图片 OCR/tesseract.js、本地 ASR、Netflix 等 DRM 平台（合规风险，Trancy 能做是商业闭源的事）。

## 五、给决策层的三句话

- 墨译在**网页 + 字幕**主线上已经完整且工程质量高；差集的价值集中在**"读 → 学"闭环**（划词 → 术语/生词 → 复习）与**"写"场景**（输入框翻译）——全部可零依赖双端落地，是下一批功能的富矿。
- **站点规则订阅生态**（学 KISS）是唯一能形成社区护城河的方向，但工作量在编辑器本身，建议放在读→学闭环之后。
- **文档翻译**用户声量最大但依赖最重，建议以"可选模块"姿态立项（独立打包、按需加载），不要为它牺牲零依赖架构。
