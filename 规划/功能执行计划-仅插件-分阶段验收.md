# 功能执行计划 — 仅插件 · 分阶段执行与验收（2026-09-23）

> **性质：纯计划，未改任何代码。**
> 设计依据：《功能规划-读学闭环与写场景-任务拆解.md》（T1–T10 的设计要点/改动清单/测试要点以该文档为准，本文不重复）。
> **范围收窄：只做 Chrome 插件，不改油猴脚本。** 本文相对拆解文档的差量见 §七。

## 〇、范围红线（「仅插件」的精确含义）

1. **`userscript/src/**` 零改动**：`entry.ts`、`localBackground.ts`、`settingsPanel.ts`、`compat/*` 全部不碰；油猴端不出现任何新功能入口。
2. **共享核心允许非破坏性演进**：`utils/`、`service/`、`translation-core/`、`entrypoints/content/`（共享管线）只增不破——新增 config 字段必须带默认值 + sanitize；公开 API 不删除、不改签名，只新增可选参数与导出。油猴重新构建后透明继承（如 MT 层的术语替换），属预期收益，不算改油猴。
3. **插件独有载体只有四类，新功能接线只落这里**：
   - **新 WXT content entrypoint**（`entrypoints/<name>.content.ts`）：油猴 import 图只触及 `content/main`（`entrypoints/content.ts` 仅是它的 re-export），新 entrypoint 天然不进油猴产物。**先例：YouTube/X 字幕正是这样做成插件独有**（`youtube.content.ts` / `x.content.ts`，油猴字幕至今未移植）；
   - `entrypoints/background.ts`：油猴用 `localBackground.ts` 复刻消息处理，不会响应新消息类型；
   - popup / options。
4. **配置天然隔离是第二重保险**：插件读 `chrome.storage.local`，油猴 shim 落 GM/localStorage，两套后端不互通——插件端配置的新功能（默认关闭）在油猴端永远惰性。
5. **不碰 ≠ 不守护**：每阶段验收含油猴不回归检查（§六），共享核心改动若破坏油猴构建/行为即打回。

## 六、验收机制（每阶段统一仪式）

1. **自动**：`npm run compile && npm test` 全量绿 → `npm run build` → `npm run build:userscript` → smoke 三链路；
2. **手动走查**：各工作包验收项逐条执行（页面 + 操作 + 预期写在上方，不留自由发挥）；
3. **油猴不回归**（红线 5）：构建成功 + `#smoke-full`/`#smoke-translate`/`#smoke-panel` 三链路 + 抽查一次真实页面翻译/还原/设置面板；
4. **收尾**：`version` 递增 → README 已知限制/文档索引更新 → 实施计划归档 `规划/进度归档/`；
5. **门语义**：任一验收项未过，不进入下一工作包；修完重跑该项及其依赖项。

## 七、移出本计划的范围（相对拆解文档的差量）

- **全部油猴端条目**：各任务 `settingsPanel.ts` 改动与油猴端验收（T1/T2/T3/T6/T7 对应行取消）；
- **Edge TTS 二期**（WS 鉴权，仅插件也需单独评估）、**T8 可视化点选元素器 v2**、**AnkiConnect 导出**（T3 二期）→ 下轮规划；
- 双端数据互通设计不再需要：T3 生词本、T6 同步只落 `chrome.storage.local`，油猴多浏览器痛点随范围收窄自然消失（WebDAV 仍保留跨设备价值）。
