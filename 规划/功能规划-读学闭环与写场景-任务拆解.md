> **性质：纯规划，未改任何代码。**

> **范围更新（同日）**：执行时收窄为仅 Chrome 插件、不改油猴脚本，执行顺序与验收见《功能执行计划-仅插件-分阶段验收.md》；本文各任务中涉及油猴端（`settingsPanel` 等）的条目对油猴端不执行，其余设计要点仍有效。

## 〇、总原则（从调研结论导出）

1. **只做差集 Top 10**，网页 + 字幕主线已收口，不再加码。
2. **顺序按依赖与价值/成本**：半天级快赢垫底 → 五星大件 → 生态级大件放后。
3. **搭车清偿**：新任务碰到 README「已知限制与待办」相关区域时顺手修复，不单独立项。
4. 每任务自带测试与验收标准；共享核心改动一律 `npm run compile && npm test` 全量跑（踩坑记录 5）。

## 二、逐任务拆解

### T1 术语表 Glossary（快赢，先行垫底）

**目标**：用户配置「原词 → 固定译名」表后，整页翻译中该词译法全页一致。AI 翻专有名词/人名的唯一轻量解。

**设计要点**

- 数据模型：条目 `{ term, translation, note?, enabled }`，存 settings 新命名空间 `glossary`（`utils/config.ts` 增字段 + sanitize 环，沿用 `sanitizeProviders` 模式）。
- **双通道生效**：
  - `openai` 兼容族 → prompt 注入：`utils/prompts.ts` 增 `buildGlossaryPrompt(entries)`，拼入 system（措辞明确「命中词必须使用指定译名」）。
  - `mt` 族（DeepL/腾讯/微软/谷歌）→ 译文后处理替换：`service/mt.ts` 出口处按词边界替换（注意英文复数/大小写变体；仅替换命中词，防「翻译腔」双重替换）。
- **省 token 关键**：发送批次前扫描段落命中哪些术语，只注入命中的（KISS「AI 术语词典」同款思路）；未命中批不带术语表。
- UI：options 新分区（增删改查 + JSON/CSV 导入导出）；油猴 `settingsPanel.ts` 同步一份精简版。

**改动清单**：`utils/config.ts`、`utils/prompts.ts`、`service/mt.ts`（替换 hook）、`entrypoints/content/trans.ts`（批次发送前命中扫描并传参）、`entrypoints/options/main.ts`、`userscript/src/settingsPanel.ts`。

**测试**：注入 prompt 快照、MT 词边界替换（复数/大小写/出现在 URL 中不误替）、glossary sanitize 环、命中扫描纯函数。

**验收**：配置术语后 AI 与 MT 两条通道整页译名一致；未配置术语时请求体积零变化。

### T2 划词/悬停查词弹窗（五星大件，M1 主体）

**目标**：任意网页选中文字 → 出词卡（词义/词性/例句/音标），为 T3 生词本与 T10 阅读卡提供统一入口。调研判定「6/6 项目共现，没有它就不完整」。

**设计要点**

- **分期收口交互**：v1 划词弹卡（`selectionchange`/mouseup + 选区非空）；v1.1 悬停翻译（hover 停留触发，段落级）。先做划词，悬停涉及大面积 hover 探测与防误触，单独收口。
- **容器**：新建 closed Shadow DOM 宿主，复用悬浮球经验（`floatingButton.ts` / `floatLogo.ts` 的宿主管理、定位、明暗适配）；弹层定位参考 `utils/popupMenuPosition.ts` 已有边界翻转逻辑。
- **查词通道**：background 新增 `lookup-word` 消息处理器，走现有服务商抽象：
  - `openai` 兼容族 → 短 prompt（词义/词性/音标/例句，temperature 0，输出 JSON，解析容错降级为纯文本展示）；
  - `mt` 族 → 明示「查词需配置 AI 服务商」（MT 无语言模型，同 AI 断句对 DeepL 的处理先例）；
  - 不内置离线词典（零依赖约束，体积不可接受）——KISS 有本地词典兜底，我们不跟。
- **双端**：油猴端经 `localBackground.ts` 同一消息通道（`fetchShim` 已通吃网络）；触发电可以复用悬浮球手势体系。
- 快捷键：`utils/shortcuts.ts` 增「查词开关」与「翻译选区」两组应用内快捷键。
- 防打扰：选区含换行超过阈值按「句段查询」而非单词处理；点外部/Esc/滚动即关；输入框内选区不触发。

**改动清单**：新增 `entrypoints/content/selection/`（宿主 + 卡片渲染 + 定位）、`entrypoints/background.ts`（`lookup-word` 处理器）、`utils/shortcuts.ts`、`utils/config.ts`（开关 + 触发方式）、options 与油猴面板 UI。

**测试**：选区提取（跨行内节点/含标点/含数字）、定位翻转（视口四边）、消息协议往返、AI 输出 JSON 解析容错三例。

**验收**：划词 1s 内出卡；iframe 与第三方 Shadow DOM 页面不崩、不留残影；油猴端功能一致；关闭后 zero DOM 泄漏（宿主移除断言）。

### T3 生词本（接住「词典查询」既有规划）

**目标**：划词卡一键收藏生词，自动带上下文，可导出。SRS/闪卡明确不做（调研建议缓做），数据结构留扩展位。

**设计要点**

- 数据模型：`{ word, translation, contextSentence, pageTitle, url, createdAt, note? }`——照 Saladict「单词上下文自动抓取」：收藏时从当前选区所在段落取原句。
- 存储：`utils/config.ts` 存储层新命名空间 `vocabbook`（插件 `chrome.storage.local` / 油猴 GM shim，链路现成）。**注明双端各自存储不互通**（与整页翻译缓存的现状一致）。
- 入口：T2 词卡加「收藏」按钮，已收藏回显状态可取消。
- 导出 v1：CSV / JSON 下载（Blob + a[download]，双端通吃）；AnkiConnect 导出二期（background fetch `http://localhost:8765` 需 host_permissions 与本机放行规则确认，README 端点校验规则已允许内网 http，届时实测）。
- 管理：options 新分区列表（搜索/删除/批量导出）。

**改动清单**：新增 `utils/vocabbook.ts`（纯函数 CRUD/导出格式化，重点可测）、`entrypoints/content/selection/`（按钮集成）、options UI、油猴面板。

**测试**：CRUD 与去重策略（同词同页覆盖/异页追加）、CSV 转义（逗号引号换行）、导出格式快照。

**验收**：划词 → 收藏 → options 查看 → 导出 CSV 用 Excel/WPS 打开不乱码；全流程在油猴端一致。

### T4 输入框翻译（写场景）

**目标**：在任意输入框输入文字后快捷键触发，弹出译文并可回填——社媒发帖与 AI 聊天双语场景。IT 主打卖点，KISS（Alt+I）/Frog/Pot 全做。

**设计要点**

- **触发**：焦点在可编辑元素（`input`/`textarea`/`contentEditable`）时按应用内快捷键（默认组可录制）；悬浮球不参与（避免与页面交互冲突）。
- **浮层**：closed Shadow DOM 小窗（原文回显 + 译文流式），复用 `streamBatchTranslation` 单段流式通道；确认回填 / 仅复制 / 取消三动作。
- **回填保 undo 栈**：`input`/`textarea` 用 `setRangeText` + 手动派发 `input` 事件；React 受限组件用原生 setter 触发（成熟零依赖做法）；`contentEditable` 用 `execCommand('insertText')`。
- **IME 安全**：组合态（compositionstart–compositionend）期间不响应触发键。
- v1 明示不支持重型富文本编辑器（Notion/飞书类自定义编辑器），README 已知限制追加一条。

**改动清单**：新增 `entrypoints/content/inputTranslate.ts`、`utils/shortcuts.ts`（新动作）、`utils/config.ts`（开关 + 快捷键）、双端 UI。

**测试**：三类可编辑元素回填（jsdom + 手动冒烟）、undo 保留断言、IME 组合态不触发、快捷键冲突时不误触。

**验收**：X/Gmail 输入框 → 快捷键 → 译文回填且 Ctrl+Z 可整体撤销；中文 IME 输入过程不打断；油猴端一致。

### T5 批量聚合 + AI 上下文会话记忆（请求层改造，顺带清偿重试待办）

**目标**：长文翻译请求数与 token 双降（Frog 宣称省 70%，我们以 fixture 实测为准），跨批术语/指代更一致。

**设计要点**

- **动态装箱**：现 `trans.ts` 为静态 `BATCH_SIZE = 8` + `MAX_BATCH_INPUT_CHARS = 6000`；改为按段落实际长度 first-fit 装箱（短段落批可到 16+，长段落自动缩批），`utils/concurrency.ts` 的 `BatchingScheduler` 扩展装箱策略，并发 3 不变。MT 族自带字节预算不受影响。
- **上下文记忆（窗口化起步）**：跨批把上一批末尾 N 段作为 `context` 注入 prompt（`BatchTranslateRequest.pageContext` 已有，扩展为 `precedingParagraphs`）。**取舍需先核对**：`translationCache.ts` 的 `cacheKey` 组成——若上下文不入 key，同一段落命中缓存时可能与其他批的措辞轻微不一致（接受，注明）；若入 key 则缓存命中率下降。v1 采用「上下文仅入 prompt、不入 key」，长文首译一致性优先。
- **重试清偿（README 待办 9）**：429 按 `Retry-After` 退避、请求超时纳入退避重试，统一进 `service/common.ts` 层，openai 与 mt 两族共用。

**改动清单**：`utils/concurrency.ts`、`entrypoints/content/trans.ts`、`utils/translateApi.ts`、`service/common.ts`（+ 各 mt 适配器对齐）、`utils/prompts.ts`（上文注入段）。

**测试**：装箱算法（全 1 字符/全超长/混合）、上文截断、退避序列（含 Retry-After 解析）、缓存命中不受上下文影响。

**验收**：fixtures 长文实测请求数下降 ≥40%、token 用量给出前后对比；术语在相邻批之间译法一致；失败重试路径与现行为兼容。

### T6 配置备份/恢复 + WebDAV 同步 + 场景 Profile（含「配置历史」规划合并）

**目标**：一键导出/导入全量配置；WebDAV 跨设备跨浏览器同步（油猴多浏览器痛点）；预设组合一键切换。

**设计要点**

- **备份**：全量 settings 序列化为带 `schemaVersion` 的 JSON 下载；导入做版本迁移与 sanitize（向前兼容）。
- **WebDAV 零依赖**：`utils/configSync.ts` 手写 DAV 客户端（PUT/GET/MKCOL + Basic auth）；插件端走 background 代发，油猴端 `fetchShim`。坚果云为首个实测目标。
- **场景 Profile**：预设包 = 服务商 + prompt 风格 + 译文样式 + 术语表开关的命名组合；切换即时生效。纯配置层，低垂果实。
- **配置历史**：本地保留最近 N 次配置快照，误改可回滚（与备份同模块）。
- **搭车清偿（README 待办 2、6）**：options 补悬浮球大小/透明度滑杆、X 站字幕开关（`xEnabled`）与 AI 断句开关（`aiSegmentation`）控件；顺带把油猴「获取模型」`prompt()` 升级为下拉（待办 3）。

**改动清单**：新增 `utils/configSync.ts`、`entrypoints/options/main.ts`（分区导航化重构，UI 重构规划已铺好 token）、油猴 `settingsPanel.ts`、`utils/config.ts`（profiles/history 字段）。

**测试**：序列化往返（含自定义 provider 全字段）、schema 迁移两例、DAV 客户端（mock fetch：401/404/成功）、Profile 切换后各读取点一致。

**验收**：油猴 A 浏览器导出 → B 导入配置一致；坚果云 WebDAV 实测上传/拉取/冲突提示；Profile 切换后无需刷新即时生效。

### T7 TTS 朗读（维持既有规划）

**目标**：整段/选区朗读。v1 零依赖系统 `speechSynthesis`；Edge TTS 二期仅插件端。

**设计要点**

- **分块**：段落 → 句子分块队列（照 Frog：句子感知分块 + 播放当前块时预取下一块），`utils/tts.ts` 纯函数层可测。
- **音色映射**：按语言自动选 voice（优先系统内对应 locale 高质量音色），可在设置指定。
- **入口**：T2 词卡「朗读」按钮 + 悬浮球菜单「朗读本页」（逐段高亮跟进可选）；划词译文/原文均可读。
- **Edge TTS 二期**：WebSocket 鉴权 token 是唯一硬点，仅插件端 background 实现，油猴端明确不做（调研标注）；开关默认关闭。

**改动清单**：新增 `utils/tts.ts`、`entrypoints/content/selection/` 与悬浮球菜单集成、`utils/config.ts`、双端 UI。

**测试**：分句纯函数（缩写/小数/引号边界）、voice 映射表、队列状态机（jsdom mock speechSynthesis：暂停/恢复/打断）。

**验收**：长段朗读无句间长停顿；中英混排自动切音色；语速可调；油猴端系统 TTS 可用。

### T8 站点规则可视化编辑 + 社区订阅（生态护城河，M3 大件）

**目标**：对剪枝误伤/漏翻站点，用户可写规则修复；规则可订阅社区仓库。调研判定「唯一能形成社区护城河的方向，但工作量在编辑器本身」。

**设计要点**

- **规则模型**：`{ hostPattern, includeSelectors, excludeSelectors, styleOverride? }`；`translation-core/dom.ts` 现有硬剪枝规则参数化出钩子，默认行为零变化。
- **优先级**：个人 > 订阅 > 全局默认（KISS 三层同构）。
- **编辑器 v1 表单式**：host + CSS 选择器 + 「试运行」按钮实时预览命中段落数（安全：只读预览，不落库不生效）；KISS 的可视化点选元素器（范围高亮/撤销重做）作为 v2 单独收口。
- **订阅**：规则仓库 = GitHub 仓库托管 JSON（社区 PR 模式），多仓库 URL 拉取 + 缓存 + 手动刷新；拉取失败静默用缓存。
- 先积累 `docs/site-rules.md` 内置规则包（官方维护），订阅机制上线后迁移为仓库。

**改动清单**：`translation-core/dom.ts`（规则钩子）、新增 `utils/siteRules.ts`（匹配/合并/订阅）、options、`entrypoints/content/trans.ts` 集成。

**测试**：匹配（通配 host/选择器合法性）、三层优先级合并、订阅解析与降级、剪枝回归测试全绿。

**验收**：对已知误伤站点（内部清单）可通过规则修复且不影响其他站点；订阅仓库更新后手动刷新生效；规则错误不致翻译流程崩溃（防御性解析）。

### ~~T9 字幕导出 SRT/TXT + 平台扩展~~（🚫 2026-09-27 用户决定不做，代码无实现）

**改动清单**：`subtitles/`（导出模块 + `trackLoader.ts` 平台分支）、字幕面板 UI、`subtitles/config.ts`。

**测试**：SRT 时间轴格式化（毫秒进位）、双语拼接、cue 空洞容错；B 站适配用 fixture 回放。

**验收**：YouTube 双语导出 SRT 可被播放器正常加载；Bilibili 字幕翻译可用后同流程导出。

### T10 AI 阅读卡（Explain + 追问）

**目标**：划词卡升级为阅读卡：按语言水平解释句子/段落，可带上下文追问。Frog/FluentRead/Trancy 三家同向的行业趋势；复用现有 AI 通道边际成本低。

**设计要点**

- 卡片两态：T2 快查态（默认）↔ 深究态（Explain：选难度「入门/进阶/母语」生成语法拆解、词义辨析、用法例句）。
- **追问**：同一会话多轮（保留卡片内历史），复用 T5 的上下文注入思路携带周边段落；会话仅存内存，关卡即弃（隐私默认）。
- 仅 `openai` 兼容族可用，MT 族置灰（同 T2 先例）。

**改动清单**：`entrypoints/content/selection/`（深究态 UI + 会话状态机）、`entrypoints/background.ts`（多轮消息或复用 `lookup-word` 扩展 role 数组）、`utils/config.ts`（默认难度）。

**测试**：会话消息拼装、难度 prompt 快照、流式中断恢复（复用现有超时/重试机制）。

**验收**：选中长难句 Explain 输出结构化解析；三轮追问上下文连贯；关闭卡片后无残留请求。

## 四、明确缓做/不做（冻结清单，来自调研 §四）

- **文档翻译**（PDF/EPUB/TXT/DOCX）：依赖最重，与零依赖+油猴端冲突最大。若立项：独立懒加载模块或服务端路线（IT 的 BabelDOC 同类），绝不进共享核心。
- **图片/区域 OCR 翻译**：tesseract.js 过重或云 OCR 另配密钥；油猴端做不了 → 双端分叉。
- **无字幕视频本地 ASR**：whisper wasm 过重或云 API 费用。
- **Netflix 等 DRM 平台字幕**：合规风险。
- **MCP 接入、剪切板监听、浏览器内置 AI 兜底**：低价值/观望，不排期。

## 五、风险与约束对照（改动前对照「踩坑记录」）

1. 新增一切 UI 走 closed Shadow DOM + 既有设计 token（防漂移测试会拦）。
2. 任何新依赖都会破坏「油猴产物禁压缩」前提——全部任务按零依赖设计，无例外。
3. GM 能力先探测再使用：T2/T4/T6 的油猴端路径都要走降级链测试。
4. 行高倍率、行距下限 1.0 等渲染红线与 T2/T10 卡片样式相关，沿用 `translationRenderer.ts` 结论。
5. 测试规模从 401 项起步，M1/M2/M3 各自全量绿后才发版；发版记得递增根 `package.json` 的 `version`（Greasy Fork `@version` 要求）。
6. 各任务开工前按仓库惯例产出会话实施计划，完成后同步归档到 `规划/进度归档/`。
