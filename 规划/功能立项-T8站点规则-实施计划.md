# 功能立项 — T8 站点规则 v1 实施计划（2026-09-25）

> **性质：纯计划，未改任何代码。** 依据《功能执行计划-仅插件-分阶段验收.md》§五 W3.4（「开工前单独立项」）。
> 调研依据：《功能调研-开源翻译项目对照.md》——站点规则是调研认定的**唯一社区护城河方向**，KISS 三件套最完整（个人 > 订阅 > 全局、范围预览、社区 repo）。
> 范围：**仅插件**（红线 3/4 同 M1/M2），共享核心改动一律非破坏性演进。

## 〇、v1 做什么、不做什么

**做**（解决真实痛点：剪枝误伤/漏翻的站点救不回来）：
- 规则模型：站点匹配 + include/exclude 选择器 + `forceInclude`（把被剪枝器漏掉的正文捞回来）；
- 规则在**候选发现层**生效：exclude 早退剪枝、forceInclude 作为独立发现通道补充候选，完整走渲染/缓存/调度管线；
- 三层优先级：个人 > 订阅 > 全局默认；
- 订阅：一个或多个 JSON 规则仓库 URL，后台拉取、本地缓存（24h 过期后后台刷新，失败静默用缓存）；
- 设置页表单编辑器（无可视化拾取器）+ 控制台试运行命令；
- 规则仓库文档格式（`docs/site-rules.md`）。

**不做（明确移出）**：可视化点选元素器（KISS 的拾取器 v2）、样式覆盖规则（v1 只管「翻不翻」不管「怎么显示」）、规则热更新推送、官方规则包内容（先空仓，靠社区填）。

## 一、架构决策（开工前落定）

1. **规则不改写剪枝谓词，而是旁路**：硬剪枝谓词 `isHardPruneElement` 是整篇翻译的地基，动它风险面覆盖全站；v1 改为——
   - `exclude` 命中 → TreeWalker `FILTER_REJECT`（子树早退，与现有剪枝同层）；
   - `forceInclude` → **独立发现通道** `root.querySelectorAll(include)`，命中的元素直接构造成候选并入管线。
   好处：默认路径零改动（回归风险面≈0），v1 需求全满足；代价：forceInclude 元素要单独做「自有节点/输入域/不可见」防御检查。
2. **订阅拉取走 background**：内容脚本 fetch 受页面 CORS 管辖（与翻译同理），MV3 的 `<all_urls>` 只让 background 免 CORS。故订阅刷新由设置页 → background `fetch-rule-repository` → 解析 → 写缓存；内容脚本**只读缓存不发请求**。
3. **规则存主配置**（`siteRules`）与 `ruleSubscriptions`（URL 列表），订阅缓存独立键 `moyi-site-rule-cache`（与译文缓存、生词本同构，避免整份配置互踩）。
4. **油猴惰性**：规则字段在共享 config 里但油猴无设置入口，默认空 → 行为零变化（红线 2 的非破坏演进）。

## 三、风险与防线

- **剪枝地基不动**：S1 只加旁路与早退，`isHardPruneElement` 行为零变化；translation-core 既有测试是回归网。
- **选择器是用户输入**：`querySelectorAll` 一律 try/catch（坏选择器跳过该条，不炸管线）；规则清洗时预校验。
- **订阅仓库是不可信输入**：JSON 解析 + 每条规则走 `sanitizeSiteRules`；2MB 上限；仅 background 发起（页面拿不到我们的网络身份）。
- **选择器性能**：`forceInclude` 通道对每个 include 选择器各跑一次 `querySelectorAll`，规则数上限 8/站点、选择器数上限 8，总查询量可控；超时/异常静默降级为默认行为。
- **油猴**：新入口不新增共享 UI；共享层只加「参数为可选、默认空」——油猴编译产物行为零变化（S5 机检验证）。
